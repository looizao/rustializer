# Require cross-version Python binaries

Rustializer requires cross-version binary compatibility across its supported conventional CPython versions, rather than separate extension binaries for each Python minor version. This adds an initial constraint to native class construction and packaging in exchange for shared binaries across Python versions. The intended route is CPython's Stable ABI with a Python 3.10 minimum, subject to verifying that it can preserve the agreed native class and serializer contracts; operating systems and architectures still require their own compatible binaries.

The first implementation milestone tests the native object model using the same built binary across CPython 3.10 through 3.15 for a target platform. This includes native metaclass construction and subclass overrides; mutable instance dictionaries and weakrefs; the application's multiple-inheritance graphs with shared storage; string/dictionary/list subclasses; and descriptor binding, garbage collection, deepcopy, and pickle behavior. The implementation combines a shared PyO3 native storage class with heap types constructed in Rust through Stable ABI APIs, a native metaclass constructor, and Rust method descriptors. No Python facade classes implement the experiment's engine behavior.

On 2026-09-30, the Linux x86_64 experiment passed 24 object-model checks per interpreter on CPython 3.10.19, 3.11.16, 3.12.14, 3.13.9, 3.14.7, and 3.15.0rc2. Each environment installed the same Python 3.10 ABI3 wheel, and the matrix runner verified identical extension bytes by SHA-256. A strict abi3audit scan found no ABI version mismatches or violations; Cargo Clippy passed with warnings denied. The tests include Python-style method signatures, keyword binding, and collection of cycles containing saved native bound methods.

This evidence establishes feasibility for the tested object-model cases on Linux x86_64. It does not certify full DRF behavior, the Python/Django compatibility matrix, performance improvements, other platforms or architectures, or the final Python 3.15 release. The experiment is isolated in `rustializer._feasibility` and does not provide production activation. `scripts/check_abi3.py` reruns the object-model checks against one built wheel.
